# Deployment guide (IaC) — plan first, apply only when ready

Credits burn as soon as NAT Gateway, RDS, ALB, Fargate, and CloudFront exist. **Do not apply until the plan looks right.**

## 0. Prerequisites

- AWS account/credentials for the class project (`aws sts get-caller-identity`)
- Terraform `>= 1.6`
- Docker (for image builds)
- Region: **`us-east-1`** (matches diagrams; supports CloudFront VPC origins except AZ `use1-az3`, which Terraform excludes)

## 1. Configure variables

```bash
cd cloud_project/terraform
cp terraform.tfvars.example terraform.tfvars
# edit terraform.tfvars if needed
```

`terraform.tfvars` is gitignored. DB password and JWT secret are **generated by Terraform** into Secrets Manager — do not hardcode them in tfvars.

## 2. Plan only (safe)

```bash
../scripts/plan_only.sh
# or:
terraform init
terraform plan -out=tfplan
```

Review the plan for:

- `aws_nat_gateway` (ongoing hourly cost)
- `aws_db_instance` with `multi_az = true`
- `aws_lb` (internal)
- `aws_cloudfront_vpc_origin` + `aws_cloudfront_distribution`
- ECS services desired count 2 / 2

## 3. Apply (only when confident)

```bash
terraform apply tfplan
```

VPC origin creation can take **up to ~15–20 minutes**.

**Expected gap after first apply:** ECR repos exist but may have **no images yet**, so ECS tasks can fail to pull until you push. That is normal.

## 4. Build and push images

From repo root (with Docker running):

```bash
chmod +x cloud_project/scripts/*.sh
./cloud_project/scripts/build_and_push.sh
```

This builds:

- Frontend: `cloud_project/docker/frontend.Dockerfile`
- Backend: `backend/Dockerfile` (repo-root context)

Then forces new ECS deployments.

## 5. Database schema + quick-test profiles (required)

RDS starts empty. **Always** run the AWS data bootstrap after images are pushed — this is what makes the Sai / Siddhardth quick-test buttons work after a destroy/re-apply:

```bash
./cloud_project/scripts/bootstrap_aws_data.sh
```

That single script (idempotent) will:

1. Apply schema migrations + create `paylink_api`
2. Seed the banks catalog
3. Seed **Sai / Siddhardth** demo profiles (and sample accounts/history)
4. Verify `POST /api/auth/demo` returns 200 for both usernames

`./cloud_project/scripts/run_migrations_ecs.sh` also seeds demo profiles at the end (so migrations alone cannot leave quick-test as 503).  
`./cloud_project/scripts/seed_demo_ecs.sh` can re-seed only the demo users if needed.

Without step 3, `/api/auth/demo` returns **503 Test profile is temporarily unavailable** even though the UI shows the quick-test buttons (`PUBLIC_DEMO_ENABLED=true`).

## 6. Verify

```bash
CF_URL=$(terraform -chdir=cloud_project/terraform output -raw cloudfront_url)
curl -sS "$CF_URL/api/health"
open "$CF_URL"   # or browser
```

Also check:

- ECS services: running task count ≥ 2 each
- ALB target groups: healthy
- CloudWatch dashboard: `paylink-ops`
- CloudFront distribution status: Deployed

## 7. Tear down (stop the burn)

```bash
cd cloud_project/terraform
terraform destroy
```

Confirm NAT, RDS, ALB, and CloudFront are gone in the console afterward.

## Phased apply (optional, safer for credits)

If you want images ready before ECS tries to start:

```bash
terraform apply -target=aws_ecr_repository.frontend -target=aws_ecr_repository.backend
./cloud_project/scripts/build_and_push.sh   # will fail force-deploy until services exist — push is enough
terraform apply
```

Or push immediately after full apply; ECS will recover once images appear.

## Rollback / failure notes

- Failed ECS deploy → check `/ecs/paylink/frontend` and `/backend` log groups.
- CloudFront 504 → VPC origin not ready, ALB SG missing CloudFront prefix list, or unhealthy targets.
- RDS connection errors → SG, wrong secret, or migrations not applied.
